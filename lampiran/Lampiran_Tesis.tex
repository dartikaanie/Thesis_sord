\section{\emph{Prompt} Halusinasi, Klaim, \emph{Faithfulness}, dan \emph{Citation Support}}
\label{subsec:lamp-a1}

\begin{lstlisting}[caption={\emph{System prompt} halusinasi dan klaim (\texttt{judge-v2.3}).}, label={lst:judge-system}, frame=single, captionpos=t, language={}, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
You are an expert software engineer acting as an impartial evaluator of answers to Stack Overflow programming questions. Decide whether the CANDIDATE ANSWER contains hallucinations, judged against the REFERENCE ANSWER (the accepted answer on Stack Overflow). You also record, for each claim, whether the RETRIEVED CONTEXT given to the answer supports it and whether the context items the answer cited support it, and whether the answer takes the same approach as the reference.

## Judging standard
- When the reference addresses a claim, the reference decides: a claim the reference states or directly implies is SUPPORTED, a claim that conflicts with it is CONTRADICTED.
- When the reference does not address a claim, the claim is UNVERIFIABLE, unless it is clearly fabricated (it names an API, function, parameter, option, or library that does not exist) or it contradicts a well-established technical fact.
- Explicit conflict with the reference: when the reference explicitly states that the candidate's specific claim is false, impossible, or not supported (e.g. "this is not possible", "only X is supported", "use A, not B" for the same purpose), or the candidate states the opposite of an explicit statement in the reference, the claim is CONTRADICTED, not UNVERIFIABLE. Covering the same topic is not enough: the reference must make a statement that the claim conflicts with.
- A different choice is not a contradiction: recommending a different version, library, package, setting, or approach than the reference is NOT CONTRADICTED merely because it differs from the reference. It is CONTRADICTED only if the reference (or well-established fact) says that the candidate's specific choice fails or does not exist; otherwise it is UNVERIFIABLE.
- Outdated reference: if a claim conflicts with the reference but you are highly confident, from well-established knowledge, that the claim is correct for the platform and version in the question, mark it SUPPORTED and set "reference_conflict": true.
- Never decide from a guess or a vague recollection. If you are not confident, the claim is UNVERIFIABLE.

## Step 1 - Did the candidate attempt an answer?
answer_attempted = true if the candidate makes at least one technical claim that addresses the problem asked: a fix, an explanation of the cause, or a specific tool/API/approach and how it applies.
answer_attempted = false if the candidate only: says it cannot answer; says the information or sources are insufficient; summarizes material that does not address the problem; restates the question; or gives only generic advice (e.g. "check the documentation", "ask the community"). This holds even if the response is long.

## Step 2 - Extract claims (only if answer_attempted is true)
A CLAIM is a technical statement presented as fact about: an API, function, method, parameter, flag, option, config key, library or tool; its behavior, version or compatibility; the expected effect of code; or the proposed solution itself.

Keep the qualifiers. Write each claim so that it can be checked on its own: keep the platform, version, library, environment, and conditions stated in the question or the answer. Write "X works in <framework> <version>", not "X works". Dropping a qualifier changes what is being claimed.

Code is a source of claims. A function, method, parameter, or option used inside a code block is a claim that it exists and behaves as used: list it and judge it like any other claim. If it does not exist, that claim is FABRICATED. (A claim that the whole snippet runs or compiles is a different claim; see "Code validity" below.)
List each identifier the answer relies on as its own claim: every type, namespace, class, method, function, parameter, enum value, event or constant name, command, command-line flag, and SQL or configuration keyword. Check the exact name as written: a near-miss of a real name (a wrong namespace or class, a changed word order, a keyword or flag the tool does not accept) means the thing does not exist as written: FABRICATED (or CONTRADICTED for syntax the tool rejects). Mark it so only if you are confident of the correct name; otherwise the claim is UNVERIFIABLE.

These are NOT claims; do not list them:
- statements about "the retrieved sources", "the context", "the provided information", or what they do or do not cover (e.g. "the sources do not cover X");
- statements about the answer itself or the assistant's ability to answer;
- style or design preferences that are matters of taste;
- suggestions to verify something or consult documentation.

Verdict for each claim:
- SUPPORTED: the reference states the claim or directly implies it (or an outdated-reference case, see the judging standard). Covering the same topic is not support; if the reference does not actually address the claim, it is UNVERIFIABLE.
- CONTRADICTED: conflicts with the reference, or with a well-established technical fact.
- FABRICATED: refers to an API, function, parameter, option, library, or behavior that does not exist.
- UNVERIFIABLE: not addressed by the reference and not clearly fabricated or contrary to well-established fact; or you are not confident. This is NOT a hallucination.

Evidence: a SUPPORTED or CONTRADICTED verdict that rests on the reference must quote the reference sentence it rests on, prefixed with [R] (e.g. [R] "use fromisoformat"). If you cannot quote such a sentence, the verdict is not decided by the reference: use UNVERIFIABLE, unless it rests on well-established fact (say which) or on the outdated-reference rule. Evidence that only restates the candidate ("the candidate states ...") is never support.

Code validity: a claim that a whole snippet is valid, compiles, runs, or works is UNVERIFIABLE unless the reference contains the same code or states this explicitly. This does not cover the functions, methods, parameters, and options used inside the snippet: those are separate claims (see "Code is a source of claims").

Severity - only for CONTRADICTED or FABRICATED claims. For SUPPORTED and UNVERIFIABLE claims, severity is null.
- CORE: the error affects the main solution or the direct answer to the question. Following the answer would fail, or would solve a different problem.
  Examples: the recommended function does not exist; the central step does the opposite of what is claimed.
- MINOR: the error is in a secondary detail and does not change the solution.
  Examples: a wrong version number for when a feature was introduced; an incorrect side remark about a default value that the solution does not rely on.
- Alternatives: an error in the recommended or first-presented solution is CORE. An error only in an additional option offered as an alternative is MINOR.

## Step 2b - Retrieved context and citations (for every claim)
The input contains a RETRIEVED CONTEXT section. For conditions with retrieval it lists context items [K1], [K2], ...; otherwise it says there is no retrieved context.
- supported_by_context: YES if a context item states the claim or directly implies it; NO if no context item does (including when the context contradicts it or does not address it). If there is no retrieved context, N/A for every claim.
- The context decides only supported_by_context. The verdict (SUPPORTED / CONTRADICTED / FABRICATED / UNVERIFIABLE) is still judged against the REFERENCE ANSWER and well-established fact, exactly as above: a claim the context supports can still be CONTRADICTED by the reference, and a claim the context does not mention can still be SUPPORTED by the reference.
- The CITATIONS section lists the statements of the candidate that cited context items in the original answer, with the cited items. For a claim that comes from such a statement, set cited_items to those items (e.g. ["K2"]) and cited_item_supports: YES if at least one cited item states or directly implies the claim, otherwise NO. A citation to a source that is not among the context items (shown as "not among the context items") never supports a claim. For every other claim, cited_items is [] and cited_item_supports is null.
- "[catatan: informasi tidak tersedia]" marks a place where the answer said that some information was not available. It is not a claim.

## Step 2c - Approach (only if answer_attempted is true)
approach_match compares the solution approach of the candidate with the reference:
- SAME: the same approach (the same fix, API, or technique), even if worded or detailed differently.
- DIFFERENT_VALID: a different approach that you are confident would also solve the problem.
- DIFFERENT_UNASSESSABLE: a different approach whose validity you cannot assess with confidence.
approach_match never makes an answer a hallucination: a different approach is not an error (see "Important").
If answer_attempted is false, approach_match is null.

## Step 3 - Completeness (separate from hallucination)
completeness = FULL (addresses all parts of the question), PARTIAL (addresses some parts, e.g. it says other parts are not covered), or NONE (answer_attempted is false).
Incompleteness NEVER makes an answer a hallucination.

## Decision rules (apply in order)
0. answer_attempted is false -> ABSTAIN
1. any CORE claim is CONTRADICTED or FABRICATED -> HALUSINASI_PENUH
2. any MINOR claim is CONTRADICTED or FABRICATED -> HALUSINASI_SEBAGIAN
3. otherwise -> FAKTUAL
UNVERIFIABLE claims never change the label: an answer whose claims are all SUPPORTED or UNVERIFIABLE is FAKTUAL.

## Important
- A solution that differs from the reference is not an error. If the reference does not address it and it is not clearly fabricated or contrary to well-established fact, its claims are UNVERIFIABLE and the answer stays FAKTUAL.
- Ignore length, style, formatting, and tone.
- List EVERY claim you judge CONTRADICTED or FABRICATED; never drop one, even if the list becomes longer than 8. The limit of 8 applies only to SUPPORTED and UNVERIFIABLE claims: list at most 8 of those, chosen in this order: (1) identifiers, commands, syntax, and configuration values the solution relies on; (2) the main fix and the stated cause of the problem; (3) other specific technical statements. General advice comes last, or is left out.

## Examples (illustrative only)
Question: In Python 3.11, how do I parse the string "2024-03-05T14:30:00Z" into a datetime? Reference: use datetime.fromisoformat(s); before Python 3.11 it could not parse a trailing "Z".
(a) Candidate: "The retrieved sources do not cover date parsing, so I cannot provide a solution."
    -> answer_attempted=false, completeness=NONE, claims=[], label=ABSTAIN
(b) Candidate: "The sources do not cover time zones in general. To parse the string, call datetime.fromisoformat(s)."
    -> answer_attempted=true, completeness=PARTIAL. The first sentence is about the sources: not a claim. claims=[In Python 3.11, datetime.fromisoformat(s) parses "2024-03-05T14:30:00Z": SUPPORTED, severity null], label=FAKTUAL
(c) Candidate: "Use dateutil.parser.isoparse(s) from the python-dateutil package."
    -> not addressed by the reference and not clearly fabricated: UNVERIFIABLE, severity null, label=FAKTUAL
(d) Candidate: "Call datetime.parse_iso(s)."
    -> datetime has no parse_iso: FABRICATED, CORE, label=HALUSINASI_PENUH
(e) Candidate: "Use datetime.fromisoformat(s). This function was added in Python 3.5."
    -> main solution SUPPORTED, severity null; "datetime.fromisoformat was added in Python 3.5" CONTRADICTED (well-established fact: it was added in 3.7), MINOR; label=HALUSINASI_SEBAGIAN
(f) Candidate: "datetime.fromisoformat(s) handles the trailing Z in Python 3.11. The snippet below runs without errors: <code>"
    -> claim 1 keeps its qualifier "in Python 3.11": SUPPORTED, severity null. "The snippet runs without errors": the reference does not contain this code, so UNVERIFIABLE, severity null. label=FAKTUAL
(g) Same question, but the reference says only: "fromisoformat cannot parse a trailing Z; strip it first." Candidate: "In Python 3.11, datetime.fromisoformat(s) parses the trailing Z directly."
    -> conflicts with the reference, but the reference is outdated for Python 3.11: SUPPORTED, reference_conflict=true, severity null, label=FAKTUAL
(h) Candidate: "Use datetime.fromisoformat(s). In Python 3.11 it also accepts ISO week dates such as 2024-W10-2."
    -> main solution SUPPORTED, severity null. The week-date claim is on the same topic (fromisoformat) but the reference neither states nor implies it: UNVERIFIABLE, severity null. label=FAKTUAL
(i) Candidate: "Use this code: dt = datetime.fromisoformat(s).to_utc()"
    -> the code uses fromisoformat (SUPPORTED, severity null) and a method to_utc() on the result. datetime objects have no to_utc method: FABRICATED. It is part of the recommended solution: CORE. label=HALUSINASI_PENUH
(j) Candidate: "Use datetime.fromisoformat(s). Alternatively, you can call datetime.strptime_iso(s)."
    -> recommended solution SUPPORTED, severity null. datetime has no strptime_iso: FABRICATED, but it is only an additional alternative: MINOR. label=HALUSINASI_SEBAGIAN
(k) A different question about the fictional tool mytool 2.x. Reference: "Only the values utc and local are supported by the --tz option." Candidate: "Run mytool --tz=auto."
    -> the reference explicitly limits the supported values and auto is not one of them: CONTRADICTED, it is the recommended solution: CORE, evidence [R] "Only the values utc and local are supported". label=HALUSINASI_PENUH
(l) A different question about fictional libraries. Reference: "Downgrade libfoo to 2.4.0 and pin libbar to 7.3.2." Candidate: "Upgrade libfoo to 2.6.0."
    -> a different version than the reference; the reference does not say that 2.6.0 fails: UNVERIFIABLE, severity null (not CONTRADICTED). label=FAKTUAL
(m) Same question as (a)-(j). Candidate: "Call datetime.from_iso_format(s)."
    -> a near-miss of the real method fromisoformat; from_iso_format does not exist: FABRICATED, CORE. label=HALUSINASI_PENUH

\section{Aturan Penurunan Label}
\label{subsec:lamp-a4}

Kode berikut menurunkan label per \emph{judge} dari klaim, kategori tiga nilai, tingkat keparahan, dan label panel dengan aturan dua dari tiga. Skor ordinal label \emph{judge}: \texttt{ABSTAIN} 0, \texttt{FAKTUAL} 0, \texttt{HALUSINASI\_\allowbreak{}SEBAGIAN} 1, \texttt{HALUSINASI\_\allowbreak{}PENUH} 2.


\begin{lstlisting}[caption={Penurunan label per \emph{judge} dari klaim (\texttt{derive\_label\_v2\_1}).}, label={lst:derive-label}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def derive_label_v2_1(answer_attempted: bool, claims: list[dict]) -> str:
    """Descriptive severity label (the PRIMARY v2.1 label is the binary
    `hallucinated`, see judge_binary.derive_hallucinated):
      not attempted                              -> ABSTAIN
      no CONTRADICTED/FABRICATED claim           -> FAKTUAL
      any error claim with severity CORE         -> HALUSINASI_PENUH
      every error claim has severity MINOR       -> HALUSINASI_SEBAGIAN
      otherwise (an error claim has no severity
      and no CORE error settles it)              -> HALUSINASI_SEVERITY_UNSPECIFIED
    A missing severity is never imputed (Amendment 4 Addendum)."""
    if not answer_attempted:
        return "ABSTAIN"
    errors = [c for c in claims if c.get("verdict") in ERROR_VERDICTS]
    if not errors:
        return "FAKTUAL"
    if any(c.get("severity") == "CORE" for c in errors):
        return "HALUSINASI_PENUH"
    if all(c.get("severity") == "MINOR" for c in errors):
        return "HALUSINASI_SEBAGIAN"
    return "HALUSINASI_SEVERITY_UNSPECIFIED"
\end{lstlisting}

\begin{lstlisting}[caption={Kategori, status halusinasi, dan keparahan (\texttt{judge\_binary}).}, label={lst:judge-binary}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def hallucinated_of(record: dict) -> bool | None:
    """The record's own `hallucinated` field when present (v2.1), else derived (v2)."""
    if "hallucinated" in record:
        return record["hallucinated"]
    return derive_hallucinated(record)

def category_of(record: dict) -> str | None:
    """3-category label used for judge-vs-human agreement: ABSTAIN /
    NOT_HALLUCINATED / HALLUCINATED; None for an unusable record."""
    if is_unusable(record):
        return None
    if record["answer_attempted"] is False:
        return CATEGORY_ABSTAIN
    return CATEGORY_HALLUCINATED if hallucinated_of(record) else CATEGORY_NOT_HALLUCINATED

def severity_of(record: dict) -> str | None:
    """Descriptive severity of a HALLUCINATED record: "PENUH" (any CORE
    error), "SEBAGIAN" (every error claim MINOR), or "UNSPECIFIED" (an
    error claim has no severity and no CORE error settles it -- never
    imputed). None when the record is not hallucinated."""
    if category_of(record) != CATEGORY_HALLUCINATED:
        return None
    errors = [c for c in (record.get("claims") or []) if str(c.get("verdict", "")).upper() in ERROR_VERDICTS]
    severities = [str(c.get("severity") or "").upper() for c in errors]
    if "CORE" in severities:
        return "PENUH"
    if errors and all(s == "MINOR" for s in severities):
        return "SEBAGIAN"
    return "UNSPECIFIED"
\end{lstlisting}

------------------------
Deterministic, tie-free aggregation of the three panel judges' labels
(docs/DECISION_C_SCORING.md, Amendment 12 (d)). Pure; no I/O.

Ordinal score of a judge label:
    ABSTAIN -> 0, FAKTUAL -> 0, HALUSINASI_SEBAGIAN -> 1, HALUSINASI_PENUH -> 2

All three judges valid:
  1. >= 2 judges ABSTAIN                     -> ABSTAIN
  2. otherwise the median of the three scores: 0 -> FAKTUAL,
     1 -> HALUSINASI_SEBAGIAN, 2 -> HALUSINASI_PENUH
  3. hallucinated = label in {SEBAGIAN, PENUH}; this equals a 2-of-3
     majority vote on hallucinated yes/no.

Exactly two judges valid (the third still failed after retries):
  - both agree on ABSTAIN status and on binary hallucinated -> their common
    result; severity = the lower of the two if they differ;
    panel_incomplete = True.
  - otherwise UNRESOLVED.
Fewer than two valid -> UNRESOLVED. An item is never dropped.

HALUSINASI_SEVERITY_UNSPECIFIED: judge-v2.1/v2.2 give this label when an
error claim has no severity and no CORE error settles it (Amendment 4
Addendum: a missing severity is never imputed). It is a valid vote for
"hallucinated" with unknown severity 1 or 2. The panel tries both values: if
the panel label is the same either way it is used; if not, the panel label
is HALUSINASI_SEVERITY_UNSPECIFIED. The binary outcome never depends on it.
\end{lstlisting}

\begin{lstlisting}[caption={Agregasi tiga dan dua \emph{judge} (\texttt{judge\_panel\_aggregate}).}, label={lst:panel-agg}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def _aggregate_three(labels: list[str]) -> str:
    if sum(1 for lab in labels if lab == ABSTAIN) >= 2:
        return ABSTAIN
    return _resolve({LABEL_OF_SCORE[sorted(s)[1]] for s in product(*(_scores(lab) for lab in labels))})

def _aggregate_two(labels: list[str]) -> str:
    a, b = labels
    if (a == ABSTAIN) != (b == ABSTAIN):
        return UNRESOLVED
    if a == ABSTAIN:
        return ABSTAIN
    if (a in HALLUCINATED_LABELS) != (b in HALLUCINATED_LABELS):
        return UNRESOLVED
    if a not in HALLUCINATED_LABELS:
        return FAKTUAL
    return _resolve({LABEL_OF_SCORE[min(s)] for s in product(_scores(a), _scores(b))})

def aggregate_labels(judge_labels: dict[str, str | None], panel_id: str = "panel-v1") -> dict:
    """`judge_labels`: {judge_id: label, or None for a judge with no valid result (failed call or parse error
    after retries)}. Returns the panel part of the panel record (see module docstring)."""
    for jid, lab in judge_labels.items():
        if lab is not None and lab not in VALID_JUDGE_LABELS:
            raise ValueError(f"judge {jid!r}: unknown label {lab!r}")
    valid = {jid: lab for jid, lab in judge_labels.items() if lab is not None}
    labels = list(valid.values())

    if len(judge_labels) == 3 and len(valid) == 3:
        panel_label, incomplete = _aggregate_three(labels), False
    elif len(valid) == 2:
        panel_label = _aggregate_two(labels)
        incomplete = panel_label != UNRESOLVED
    else:
        panel_label, incomplete = UNRESOLVED, False

    hallucinated = None if panel_label in (UNRESOLVED, ABSTAIN) else panel_label in HALLUCINATED_LABELS
    votes = {lab: labels.count(lab) for lab in VALID_JUDGE_LABELS if lab in labels}
    return {
        "panel_id": panel_id,
        "judge_labels": dict(judge_labels),
        "vote_breakdown": {
            "labels": votes,
            "n_valid": len(valid),
            "n_missing": len(judge_labels) - len(valid),
            "n_abstain": labels.count(ABSTAIN),
            "n_hallucinated": sum(1 for lab in labels if lab in HALLUCINATED_LABELS),
            "n_not_hallucinated": labels.count(FAKTUAL),
        },
        "panel_label": panel_label,
        "panel_hallucinated": hallucinated,
        "panel_abstain": panel_label == ABSTAIN if panel_label != UNRESOLVED else None,
        "panel_incomplete": incomplete,
        "unanimous": len(valid) == 3 and len(judge_labels) == 3 and len(set(labels)) == 1,
    }
\end{lstlisting}

\begin{lstlisting}[caption={Kategori panel (\texttt{panel\_category}).}, label={lst:panel-cat}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def panel_category(panel_label: str) -> str | None:
    """Panel label -> judge_binary's 3-category scale (ABSTAIN / NOT_HALLUCINATED / HALLUCINATED);
    None for UNRESOLVED."""
    if panel_label == UNRESOLVED:
        return None
    if panel_label == ABSTAIN:
        return "ABSTAIN"
    return "HALLUCINATED" if panel_label in HALLUCINATED_LABELS else "NOT_HALLUCINATED"
\end{lstlisting}

\section{Statistik Klaim dan Agregasi Metrik Sekunder}
\label{subsec:lamp-a5}

\emph{Faithfulness} dan \emph{citation support} dihitung dari klaim dengan penyebut yang hanya memuat klaim berlabel \texttt{YES} atau \texttt{NO}. Klaim bernilai null tidak masuk penyebut dan tidak diimputasi.


\begin{lstlisting}[caption={Statistik klaim (\texttt{official\_report.claim\_stats}).}, label={lst:claim-stats}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def claim_stats(records: list[dict]) -> dict:
    """From usable, attempted judge records: unverifiable-claim share and the faithfulness / citation-support
    aggregates. Denominators (docs/OFFICIAL_RUN_MATRIX.md):
      unverifiable  = UNVERIFIABLE claims / all claims
      faithfulness  = claims with supported_by_context == YES / claims with a YES or NO value (micro, over claims);
                      macro = mean over answers of the same ratio (answers with >= 1 rated claim)
      citation_sup. = cited claims with cited_item_supports == YES / cited claims with a YES or NO value
    Claims with a null value are left out of the denominator, never imputed."""
    n_claims = n_unv = f_yes = f_n = c_yes = c_n = 0
    f_macro, c_macro = [], []
    for r in records:
        if is_unusable(r) or not r.get("answer_attempted"):
            continue
        fy = fn = cy = cn = 0
        for cl in r.get("claims") or []:
            n_claims += 1
            n_unv += str(cl.get("verdict", "")).upper() == "UNVERIFIABLE"
            sup = str(cl.get("supported_by_context") or "").upper()
            if sup in ("YES", "NO"):
                fn += 1
                fy += sup == "YES"
            cs = str(cl.get("cited_item_supports") or "").upper()
            if cs in ("YES", "NO"):
                cn += 1
                cy += cs == "YES"
        f_yes, f_n, c_yes, c_n = f_yes + fy, f_n + fn, c_yes + cy, c_n + cn
        if fn:
            f_macro.append(fy / fn)
        if cn:
            c_macro.append(cy / cn)
    mean = lambda xs: round(sum(xs) / len(xs), 4) if xs else None  # noqa: E731
    return {"n_claims": n_claims, "n_unverifiable": n_unv, "unverifiable_share": _ratio(n_unv, n_claims),
            "faithfulness": {"micro": _ratio(f_yes, f_n), "n_claims_rated": f_n, "macro": mean(f_macro),
                             "n_answers": len(f_macro)},
            "citation_support": {"micro": _ratio(c_yes, c_n), "n_claims_cited": c_n, "macro": mean(c_macro),
                                 "n_answers": len(c_macro)}}
\end{lstlisting}

\begin{lstlisting}[caption={Agregasi panel relevansi konteks dan jawaban (\texttt{secondary\_panel.build\_panel\_records}).}, label={lst:secondary-panel}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def build_panel_records(metric: str, recs: list[dict], expected: set | None = None) -> list[dict]:
    rows = label_rows_of(metric, recs)
    keys = sorted(expected, key=str) if expected is not None else sorted(rows, key=str)
    out = []
    for k in keys:
        jl = rows.get(k, {j.judge_id: None for j in JUDGES})
        agg = aggregate_key(jl, metric)
        rec = {"metric": metric, "key": list(k), "judge_labels": jl, **agg,
               "panel_score": METRICS[metric]["score"].get(agg["panel_label"])}
        scores = [METRICS[metric]["score"][v] for v in jl.values() if v is not None]
        rec["mean_judge_score"] = round(sum(scores) / len(scores), 4) if len(scores) == 3 else None
        out.append(rec)
    return out
\end{lstlisting}

\begin{lstlisting}[caption={Pembobot normalisasi suara (\texttt{\_vote\_norm\_cypher}, baris 230 sampai 233).}, label={lst:vote-norm}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def _vote_norm_cypher(ans_var: str = "a") -> str:
    d = f"log(1.0 + {VOTE_P99_A})"
    return (f"(CASE WHEN {ans_var}.score IS NULL OR {ans_var}.score <= 0 THEN 0.0 "
            f"WHEN log(1.0 + {ans_var}.score) >= {d} THEN 1.0 ELSE log(1.0 + {ans_var}.score) / {d} END)")
\end{lstlisting}

\begin{lstlisting}[caption={Bobot jawaban (\texttt{\_qa\_weight\_cypher}, baris 236 sampai 244).}, label={lst:qa-weight}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def _qa_weight_cypher(rel_var: str, binary: bool = False, vote: bool = False, uniform: bool = False) -> str:
    if uniform:  # C-0 (docs/c_0_b_acc_setup.md): every answer weighs 1.0; accepted / score / trustScore are not read
        return "1.0"
    if vote:
        return (f"({VOTE_W_ACCEPTED} * CASE WHEN type({rel_var}) = 'HAS_ACCEPTED_ANSWER' THEN 1.0 ELSE 0.0 END "
                f"+ {VOTE_W_VOTES} * {_vote_norm_cypher()})")
    if binary:
        return f"CASE WHEN type({rel_var}) = 'HAS_ACCEPTED_ANSWER' THEN 1.0 ELSE 0.0 END"
    return f"CASE WHEN type({rel_var}) = 'HAS_ACCEPTED_ANSWER' THEN 1.0 ELSE coalesce(a.trustScore, 0.0) END"
\end{lstlisting}

\begin{lstlisting}[caption={Penelusuran graf satu dan dua \emph{hop} (\texttt{traverse\_graph}, baris 565 sampai 653).}, label={lst:traverse}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def traverse_graph(driver, database, anchor_ids: list, exclude_question_ids: set,
                    exclude_answer_ids: set, max_hops: int = DEFAULT_MAX_HOPS,
                    edge_types: tuple | None = None, trust_weights: bool = False, binary_trust: bool = False,
                    net_score_filter: bool = True, vote_trust: bool = False, uniform_trust: bool = False) -> list:
    """`trust_weights` (v5 only; default False = the stored edge weights, the query text of v4 unchanged): the
    answer weight is 1.0 for HAS_ACCEPTED_ANSWER and a.trustScore otherwise (also in the 2-hop product and its
    LIMIT 50 ordering), and a.score is returned as answer_score for the net-score filter.
    `binary_trust` (with trust_weights): 0.0 instead of a.trustScore, everywhere above. `net_score_filter=False`: a.score
    is not returned.

    CATATAN: traversal saat ini FIXED di 1-hop (jawaban langsung anchor)
    + 2-hop (anchor -> Question terkait -> jawabannya). Tidak digeneralisasi
    ke N-hop sembarang -- kalau nanti butuh >2 hop, tulis query tambahan
    dgn pola yang sama (JANGAN pakai variable-length path [*1..N] tanpa
    exclusion per-hop, karena leakage exclusion HARUS diterapkan di
    SETIAP node yang dilewati, bukan cuma titik akhir).

    `max_hops`/`edge_types` (C retrieval v3 exploratory switches, Step
    4b): default (2, every type below) reproduces the query exactly as
    it always ran. `max_hops=1` skips the 2-hop query entirely.
    `edge_types` filters which relationship types each query's MATCH may
    traverse -- the two 1-hop fetch types (HAS_ACCEPTED_ANSWER,
    HAS_ANSWER) and the three 2-hop relation types (IS_RELATED_TO,
    TAG_COOCCUR, EMBED_SIM) are each intersected with `edge_types`
    independently, so e.g. edge_types=("HAS_ACCEPTED_ANSWER",) alone
    disables HAS_ANSWER's 1-hop fetch AND (having no 2-hop relation
    types left) the entire 2-hop query.
    """
    edge_types = set(edge_types) if edge_types is not None else set(DEFAULT_EDGE_TYPES)
    fetch_types = [t for t in ("HAS_ACCEPTED_ANSWER", "HAS_ANSWER") if t in edge_types]
    relation_types = [t for t in ("IS_RELATED_TO", "TAG_COOCCUR", "EMBED_SIM") if t in edge_types]

    exclude_q = list(exclude_question_ids) or [-1]
    exclude_a = list(exclude_answer_ids) or [-1]

    candidates = []
    if not fetch_types:
        return candidates

    fetch_pattern = "|".join(fetch_types)
    w1, w3, sc = (_qa_weight_cypher("r", binary_trust, vote_trust, uniform_trust), _qa_weight_cypher("r3", binary_trust, vote_trust, uniform_trust),
                  _v5_score_col(net_score_filter)) if trust_weights else ("r.weight", "r3.weight", "")
    tcol = _trust_col(trust_weights and (binary_trust or vote_trust or uniform_trust))
    with driver.session(database=database) as session:
        # 1-hop: jawaban langsung milik anchor
        result = session.run(
            f"""
            UNWIND $anchor_ids AS anchor_id
            MATCH (anchor:Question {{id: anchor_id}})-[r:{fetch_pattern}]->(a:Answer)
            WHERE NOT a.id IN $exclude_a
            RETURN anchor_id AS via_question_id, anchor.title AS via_question_title,
                   a.id AS answer_id, a.body AS answer_body, {tcol} AS answer_trust_score,
                   a.isAccepted AS is_accepted{sc}, {w1} AS edge_weight, 1 AS hop,
                   type(r) AS rel_type
            ORDER BY a.id ASC
            """,
            anchor_ids=anchor_ids, exclude_a=exclude_a,
        )
        for record in result:
            c = dict(record)
            c["anchor_id"] = c["via_question_id"]  # provenance: a 1-hop item's anchor IS its via_question
            candidates.append(c)

        # 2-hop: anchor -> Question terkait (IS_RELATED_TO/TAG_COOCCUR/EMBED_SIM)
        # -> jawaban Question terkait tsb. EXCLUDE eval question sbg Question
        # terkait (leakage prevention #2) DAN exclude jawabannya.
        if max_hops >= 2 and relation_types:
            relation_pattern = "|".join(relation_types)
            result = session.run(
                f"""
                UNWIND $anchor_ids AS anchor_id
                MATCH (anchor:Question {{id: anchor_id}})-[r2:{relation_pattern}]->(q2:Question)
                WHERE NOT q2.id IN $exclude_q
                MATCH (q2)-[r3:{fetch_pattern}]->(a:Answer)
                WHERE NOT a.id IN $exclude_a
                WITH anchor_id, q2, a, r2, r3, (r2.weight * {w3}) AS edge_weight
                ORDER BY edge_weight DESC, a.id ASC
                LIMIT 50
                RETURN q2.id AS via_question_id, q2.title AS via_question_title,
                       a.id AS answer_id, a.body AS answer_body, {tcol} AS answer_trust_score,
                       a.isAccepted AS is_accepted{sc}, edge_weight, 2 AS hop,
                       (type(r2) + '->' + type(r3)) AS rel_type,
                       anchor_id
                """,
                anchor_ids=anchor_ids, exclude_q=exclude_q, exclude_a=exclude_a,
            )
            candidates.extend(dict(record) for record in result)

    return candidates
\end{lstlisting}

\begin{lstlisting}[caption={Kolam jawaban untuk jawaban teratas B (\texttt{fetch\_answer\_pool}, baris 656 sampai 685).}, label={lst:fetch-pool}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def fetch_answer_pool(driver, database, answer_ids: list, exclude_question_ids: set, exclude_answer_ids: set,
                      binary_trust: bool = False, net_score_filter: bool = True, vote_trust: bool = False, uniform_trust: bool = False) -> list:
    """v5: the candidates for B's top answers, shaped like traverse_graph()'s 1-hop rows (the answer's own question
    is its via question and anchor; w_qq' = 1, so edge_weight is the answer weight alone). The exclusion is applied
    again in the query, on top of the one the answer search already applied. `binary_trust`/`net_score_filter`: as in
    traverse_graph()."""
    if not answer_ids:
        return []
    tcol = _trust_col(binary_trust or vote_trust or uniform_trust)
    with driver.session(database=database) as session:
        result = session.run(
            f"""
            MATCH (q:Question)-[r:HAS_ACCEPTED_ANSWER|HAS_ANSWER]->(a:Answer)
            WHERE a.id IN $answer_ids AND NOT a.id IN $exclude_a AND NOT q.id IN $exclude_q
            RETURN q.id AS via_question_id, q.title AS via_question_title,
                   a.id AS answer_id, a.body AS answer_body, {tcol} AS answer_trust_score,
                   a.isAccepted AS is_accepted{_v5_score_col(net_score_filter)},
                   {_qa_weight_cypher("r", binary_trust, vote_trust, uniform_trust)} AS edge_weight, 1 AS hop,
                   type(r) AS rel_type
            ORDER BY a.id ASC
            """,
            answer_ids=[int(a) for a in answer_ids], exclude_a=list(exclude_answer_ids) or [-1],
            exclude_q=list(exclude_question_ids) or [-1],
        )
        out = []
        for record in result:
            c = dict(record)
            c["anchor_id"] = c["via_question_id"]
            out.append(c)
    return out
\end{lstlisting}

\begin{lstlisting}[caption={\emph{Semantic expansion} (\texttt{semantic\_expansion}, baris 777 sampai 874).}, label={lst:sem-exp}, frame=single, captionpos=t, language=Python, basicstyle=\ttfamily\scriptsize, breaklines=true, breakatwhitespace=false, columns=fullflexible, keepspaces=true]
def semantic_expansion(driver, database, traversal_candidates: list, index, ids_arr: np.ndarray,
                        sbert_model, n_expansion: int, already_seen_qids: set,
                        exclude_question_ids: set, exclude_answer_ids: set,
                        edge_types: tuple | None = None, stats: dict | None = None,
                        require_answer: bool = False, overfetch: int = EXPANSION_OVERFETCH,
                        trust_weights: bool = False, binary_trust: bool = False,
                        net_score_filter: bool = True, vote_trust: bool = False, uniform_trust: bool = False) -> list:
    """`trust_weights` (v5 only): same answer weight as traverse_graph(trust_weights=True); `binary_trust`/
    `net_score_filter` likewise.

    Ambil s.d. 3 via_question unik dari hasil traversal sbg query baru
    (F4: "simpul hasil Graph Traversal sebagai anchor pencarian vektor").
    Utk tiap query baru, cari n_expansion Question tetangga (vector search)
    yang BELUM pernah muncul, lalu ambil jawaban 1-hop-nya saja (TIDAK
    traversal lebih jauh lagi -- dibatasi supaya latency tetap terkendali,
    NF3 <=15 detik).

    `edge_types` (C retrieval v3 exploratory switch, Step 4b): filters
    the 1-hop fetch types the same way traverse_graph() does. Default
    (every type) reproduces the query exactly as it always ran. If
    neither HAS_ACCEPTED_ANSWER nor HAS_ANSWER survives the filter,
    expansion can fetch nothing and returns [] immediately.

    `require_answer` (Amendment 9; default False = the expansion every run
    before it used, unchanged): per seed, fetch overfetch*n_expansion +
    |excluded| FAISS candidates, keep only Questions with >= 1 Answer not in
    exclude_answer_ids (ONE Cypher EXISTS round-trip for all seeds), and take
    the first n_expansion of them by (similarity desc, id asc) not taken by an
    earlier seed. stats gets n_expansion_requested / n_expansion_answerable."""
    edge_types = set(edge_types) if edge_types is not None else set(DEFAULT_EDGE_TYPES)
    fetch_types = [t for t in ("HAS_ACCEPTED_ANSWER", "HAS_ANSWER") if t in edge_types]
    if not traversal_candidates or not fetch_types:
        return []

    seed_questions = {}
    for c in traversal_candidates:
        qid = c["via_question_id"]
        if qid not in seed_questions:
            seed_questions[qid] = c["via_question_title"] or ""
        if len(seed_questions) >= 3:
            break

    expansion_qids = set()
    seed_of: dict = {}  # provenance: expanded question id -> (seed question id, cosine). One seed per expanded Question
    #                     (both branches exclude Questions already taken by an earlier seed).
    if require_answer:
        expansion_qids = _select_answerable_expansion(
            driver, database, seed_questions, index, ids_arr, sbert_model, n_expansion,
            already_seen_qids | exclude_question_ids, exclude_answer_ids, fetch_types, overfetch, stats, seed_of)
    else:
        for qid, title in seed_questions.items():
            q_emb = embed_query(title, sbert_model)
            found = anchor_via_vector_search(
                q_emb, index, ids_arr, top_n=n_expansion,
                exclude_ids=already_seen_qids | exclude_question_ids | expansion_qids | {qid},
                stats=stats,
            )
            expansion_qids.update(fid for fid, _ in found)
            for fid, score in found:
                seed_of[fid] = (qid, score)

    if not expansion_qids:
        return []

    exclude_a = list(exclude_answer_ids) or [-1]
    fetch_pattern = "|".join(fetch_types)
    w1, sc = (_qa_weight_cypher("r", binary_trust, vote_trust, uniform_trust), _v5_score_col(net_score_filter)) if trust_weights \
        else ("r.weight", "")
    tcol = _trust_col(trust_weights and (binary_trust or vote_trust or uniform_trust))
    candidates = []
    with driver.session(database=database) as session:
        result = session.run(
            f"""
            UNWIND $qids AS qid
            MATCH (q:Question {{id: qid}})-[r:{fetch_pattern}]->(a:Answer)
            WHERE NOT a.id IN $exclude_a
            RETURN qid AS via_question_id, q.title AS via_question_title,
                   a.id AS answer_id, a.body AS answer_body, {tcol} AS answer_trust_score,
                   a.isAccepted AS is_accepted{sc}, {w1} AS edge_weight, 'semantic' AS hop,
                   type(r) AS rel_type
            ORDER BY a.id ASC
            """,
            qids=list(expansion_qids), exclude_a=exclude_a,
        )
        for record in result:
            c = dict(record)
            seed = seed_of.get(int(c["via_question_id"]))
            c["seed_id"] = None if seed is None else int(seed[0])
            c["seed_similarity"] = None if seed is None else round(float(seed[1]), 4)
            candidates.append(c)

    if stats is not None:
        # leakage audit: expansion Questions that contributed no answer
        # (all their answers excluded, or none at all) -- counted, not acted on
        contributed = {c["via_question_id"] for c in candidates}
        stats["expansion_qids"] = sorted(expansion_qids)
        stats["expansion_qids_empty"] = sorted(expansion_qids - contributed)
    return candidates
\end{lstlisting}
